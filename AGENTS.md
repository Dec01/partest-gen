# partest-gen — agent instructions

You maintain a **code generator**, not a test suite. Every line you emit runs in a project
whose domain you have never seen, so it must be correct without knowing what the API is for.

## TASK

Develop and maintain `partest-gen` — the `partest-gen` CLI that turns an OpenAPI document into
a runnable pytest + `partest` monorepo: endpoints, payloads, validations, collection facades,
the priority-one stub matrix, and an optional isolated UI layer. Ship to PyPI.

## CONTEXT

- Parts: `docs/wiki/components/generator.md` · what it emits and why:
  `docs/wiki/concepts/generated-contract.md` · catalog: `docs/wiki/index.md`
- Current version, waves, what is next: `docs/wiki/status.md` — the only status source
- Procedures load on demand from `.claude/skills/`: `partest-scaffold`, `partest-gen-release`,
  `partest-gen-docs` · documentation conventions: `docs/wiki/WIKI.md`
- **Methodology is not owned here.** Subtypes, the P1 matrix and the classifier live in
  `partest.methodology`; this package reads them. A gap in classification is a `partest`
  change, not a local workaround — see `docs/wiki/decisions/methodology-upstream.md`.

## CONSTRAINTS

Red lines — violating any of these is a defect, not a trade-off:

1. **No product domain in emitted code.** Stubs, not business values: no entity DTOs, RBAC
   role lists, SQL cleanup, stand URLs, page objects or baselines. Those stay in the suite.
2. **Generated code imports public `partest.*` only.** No private names, no vendored copies of
   harness code, no forked methodology tables.
3. **Honour the banner contract.** `sync-openapi` may overwrite only files carrying
   `AUTO-GENERATED by partest-gen`. Widening that is data loss in someone's repository.
4. **The emitted UI layer stays isolated** — `src/ui/conftest.py` must never import
   `confpartest`, load OpenAPI, or start the API coverage session.
5. **Emitted tests always pass `type=` explicitly.** Inference is a fallback, not a default.
6. **Emitted cleanup goes through the tracking registry and `TEST_MARKER`.** Never emit DDL/DML,
   and never write to a database yourself — databases are read-only.
7. **Nothing private ships.** No secrets, stand URLs, absolute local paths or consumer project
   names in the package, the templates, or any page with `ships_in_wheel: true`.
8. **Do not hand-edit `partest_gen/docs/`** — it is generated by `tools/docs_build_wheel.py`.
9. **Do not bump `__version__`** unless the user explicitly asks for a release.

## FALLBACK

- Requirement ambiguous, or two readings lead to different generated code → ask, do not guess.
- Document disagrees with code → **code wins**; fix the page and its `verified:` date.
- A spec shape the emitters cannot express → emit a skipped stub with a `TODO` naming what is
  missing. Never emit code that silently tests nothing.
- Needed behaviour belongs to the harness → change `partest` and depend on the new release.
- Task needs something outside the generator (a stand, a consumer repository) → stop and say so.

## OUTPUT_FORMAT

- Changes: minimal diff in the style of the surrounding emitter; tests under `tests/`.
- Verify with `python -m pytest tests/ -q` before reporting done. Report failures with output.
- Changed what is emitted → update `tests/test_golden_suite.py`, the `components/` page,
  `CHANGELOG.md`, and the `partest-scaffold` skill in the same change.
- Touched a file listed in a page's `sources:` → refresh that page's `verified:` date.
- Reorganized documentation → append a line to `docs/wiki/log.md`.
- State plainly what you did, what you skipped, and what remains.
