# The contract of generated code

A generator that overwrites your work is worse than no generator. This page states exactly
which files the tool owns, which are yours, and what the emitted tests promise.

## 1. The banner decides ownership

Every file the generator considers its own starts with a line containing:

```text
AUTO-GENERATED by partest-gen
```

| File | On `sync-openapi` | On `--force` |
|---|---|---|
| has the banner | overwritten | overwritten |
| no banner | left alone | overwritten |

So there are two ways to keep code safe: put it in a file without the banner, or do not pass
`--force`. There is no third.

**Never hand-edit a banner file.** The edit survives until the next sync and then disappears,
which is the worst possible failure mode — it works long enough for you to rely on it. Put
your code in a sibling module and import it.

`--force` exists for the case where you regenerate a project on purpose and accept losing
local changes. If you are not sure that is what you want, it is not what you want.

## 2. What a stub promises, and what it does not

An emitted test case promises three things:

1. it **exists**, so the coverage report counts the case as present rather than missing;
2. it targets the **right operation** with the right `type=`, so it lands in the right cell of
   the matrix;
3. it **imports cleanly**, so a whole generated tree can be collected before a line is written.

It does not promise to assert anything meaningful. Most stubs are skipped and carry a `TODO`
naming what is missing — a seed record, a path parameter, a business value.

This is deliberate. A generated assertion that passes on any response would make the coverage
number rise without any testing happening, and a false green is more expensive than a red.
A skipped stub is honest: the case is known, the work is not done.

## 3. Why `type=` is always explicit

Every emitted call passes `type=` even where the harness could infer it. Inference is a
convenience for hand-written tests; in generated code it would make the coverage matrix depend
on a heuristic reading a heuristic. The stub already knows which case it is — writing it down
costs one argument and removes a whole class of silent misclassification.

## 4. What is never emitted

The generator writes structure. It does not write your product:

| Not emitted | Where it belongs |
|---|---|
| role names, credentials, permission matrices | your `rbac/roles.py`, read from the environment |
| business values inside payloads | your test, or a factory next to it |
| SQL, cleanup queries, database access of any kind | your project, through the tracking registry |
| stand URLs, tokens, secrets | your `.env`, never committed |
| page objects for real screens, visual baselines | your UI tree |

Emitted cleanup goes through the created-resource registry and the test-data marker, never
through direct deletes. A generated project should not be able to remove anything that a test
did not create.

## 5. Regeneration is not a merge

`sync-openapi` re-emits from the current specification. It does not diff against what you
have, and it does not know that a hand-written test referenced an operation that has since
been removed. After a sync that changed operations, run a collect-only pass — an import error
is how you find those, and it is much cheaper than a failing suite. See [[howto/resync]].
