## 1. Что готово (не переизобретать)

Волны G0–G6 сделаны ещё внутри `partest` и переехали как есть.

| Волна | Что дала | Где живёт |
|---|---|---|
| **G0** | целевое дерево и роадмап | [[components/generator]] |
| **G1** | IR + команды `init` / `dump-ir` | `partest_gen/ir.py`, `partest_gen/skeleton.py` |
| **G2** | `paths` + коллекции + `sync-openapi` | `partest_gen/emitters/paths.py`, `…/collections.py` |
| **G3** | payloads + validations + Default/NotAllowed | `…/payloads.py`, `…/validations.py`, `…/tests_default.py` |
| **G4** | полный набор P1-заглушек + `P1_CHECKLIST.md` | `…/tests_p1.py` |
| **G5** | глубокий UI-слой + `init-ui` | `partest_gen/ui_layout.py`, [[components/ui-layer]] |
| **G6** | playbook агента | скилл `partest-scaffold` |

Ничего из этого при выделении не переписывалось: изменились только имена импортов
(`partest.project_gen` → `partest_gen`) и упаковка. Golden-тест
`tests/test_golden_suite.py` — то же дерево, что и до выделения.

## 2. Что дальше

Незакрытых волн нет; ниже — очередь, а не обязательства.

| ID | Задача | Почему |
|---|---|---|
| **GEN-SPEC-3.1** | распознавать `webhooks` и `callbacks` OpenAPI 3.1 | сейчас молча игнорируются, а не помечаются TODO |
| **GEN-SEC-SCHEMES** | читать `securitySchemes` и раскладывать заголовки по ним | сейчас `headers.read|write` эвристика |
| **GEN-DIFF** | `sync-openapi --dry-run`, показывающий diff до записи | сейчас узнать «что перезапишется» можно только по факту |
| **GEN-EXAMPLES** | брать значения из `examples`/`example` спеки в payload-заглушки | заглушки формально верные, но пустые |
| **GEN-PLUGIN** | точка расширения для своих эмиттеров | сейчас набор эмиттеров фиксирован |

### Позже

Шаблоны в отдельных файлах вместо строк в модулях (`skeleton.py`, `ui_layout.py` — самые
крупные файлы пакета, и почти всё в них — текст). Требует решения по формату и по тому,
как это уживётся с проверкой «в шаблонах нет приватных путей».

### HOLD

Генерация тестов по трафику (HAR / прокси) вместо спеки. Другая входная модель и другая
методология — не смешивать с `--depth`, пока не будет отдельного запроса.

## 3. Совместимость с `partest`

| | |
|---|---|
| Минимум | `partest>=2.0.0` — в 2.0.0 методика разъехалась на `api/` и `ui/`, старых путей там нет сознательно |
| Что берётся | `partest.methodology.api.{classifier,matrix,subtypes}`, `partest.test_types`, `partest.tools.generate_init`, `partest.tls` (в UI-шаблоне) |
| Что эмитится | только публичный `partest.*` — см. [[decisions/methodology-upstream]] |

`partest` со своей стороны держит `partest.project_gen` как мост на этот пакет и экстру
`partest[gen]`. Мост объявлен устаревшим; срок снятия — мажорная версия `partest`.

## 4. Как обновлять эту страницу

1. Новый источник → локальный `docs/raw/<источник>/<дата>/` (вне git), старый не трогаем.
2. Переписать §2 по свежему источнику; противоречия разрешать в пользу более поздней даты
   и **явно называть** их.
3. Обновить `verified:` и добавить строку в [[log]].
