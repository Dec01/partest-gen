# Предложения

Спорное, что всплыло при работе и **не реализовано**: здесь аргументы обеих сторон, решение
за человеком. Принятое уходит в код и в [[status]], отклонённое — вычёркивается с причиной.

## 2026-10-16 · ревью исправлений 1.2.0

### (a) Смена `--depth` молча оставляет глубокие файлы без обновления

Сейчас `sync-openapi --depth resources` по дереву, сгенерированному с `--depth p1`, не трогает
P1-заглушки и не называет их брошенными — это записано в [[howto/resync]].

- **За строку в выводе:** пользователь, однажды запустивший sync с меньшей глубиной, не
  узнает, что часть сгенерированных файлов больше не обновляется; заглушки разойдутся со
  спецификацией тихо.
- **Против:** меньшая глубина — законный способ обновить только ресурсы; лишний шум в
  выводе каждого такого прогона. Если делать — одной строкой со счётчиком, без списка.

### (b) `pythonpath = .` лечит симптом

Пустой отчёт покрытия при консольном `pytest` закрыт строкой в генерируемом `pytest.ini`.
Настоящая гарантия — в `partest`: сигнал (предупреждение или ошибка), когда `confpartest`
не найден при загрузке плагина, а отчёт пуст.

- **За перенос в `partest`:** проекты, написанные руками или старыми генераторами, остаются
  без защиты; молча пустой отчёт — худший режим отказа.
- **Против того, чтобы убрать строку здесь:** она полезна и после правки в `partest` —
  набор работает одинаково под `pytest` и `python -m pytest`. Предложение — дополнить, не
  заменить. Это задача для `partest`, не для этого репозитория.

### (c) Новая публичная поверхность

По итогам ревью (2026-10-17) публичными оставлены только `find_orphans` и
`remove_orphans` (`partest_gen.emitters.__all__`, сигнатуры — [[components/generator]]);
план генерации и правила владения — приватные (`_plan_resources`, `_is_generated`, …).

- **За публичный план:** он нужен для `--dry-run` (GEN-DIFF в [[status]]) и для обвязок поверх
  генератора.
- **Против сейчас:** потребителя нет; открыть имя потом — минор, закрыть — мажор.

### (d) Честный мажор вместо отдельного признака чек-листа

**Решено 2026-10-18:** поправки ADR banner-overwrite приняты, выпуск 1.2.0; вариант не выбран.

Принятое решение (поправки в [[decisions/banner-overwrite]]) держит минор: чек-лист старого
образца остаётся пользовательским, обновляется только новый образец.

- **За 2.0.0:** один признак баннера для всех файлов, чек-листы во всех проектах сразу
  становятся актуальными; сложность «старый/новый образец» исчезает.
- **Против:** по ADR перезапись по умолчанию там, где её не было, — мажор; ради одного
  справочного файла это дорого, а отметки, сделанные по совету старого текста, были бы
  потеряны молча.

### (e) Минор без правила заготовок

**Решено 2026-10-18:** поправки ADR banner-overwrite приняты, выпуск 1.2.0; вариант не выбран.

Принятое правило (поправки в [[decisions/banner-overwrite]]) перезаписывает файл, побайтно
равный заготовке скелета.

- **Альтернатива:** скелет не пишет заготовки на пути эмиттеров, когда следом идёт
  спецификация (`from-openapi`, `init --openapi`), а при голом `init` пишет их уже с баннером.
  Новые деревья тогда целы без особого признака; старые деревья 1.1.0 чинятся `--force`
  или удалением заготовок руками.
- **За альтернативу:** признак владения остаётся один — баннер; нет списка «известных
  текстов», который надо пополнять при каждой правке скелета.
- **Риск принятого правила:** заготовка `"""Package."""` у `collections/__init__.py`,
  `endpoints/__init__.py`, `validations/__init__.py` неотличима от такого же файла,
  оставленного пользователем нарочно. Если коллекции написаны руками, а `__init__` не тронут,
  sync заменит его сгенерированным с импортами — поведение импорта пакета изменится.
- **Против альтернативы:** заготовки с баннером при голом `init` — это новый «свой» файл там,
  где его не было; старые деревья требуют ручного шага, который правило заготовок снимает.
- **Версия:** по букве «Что было бы мажорной версией» в ADR правило заготовок само — новый
  признак своего файла, то есть мажор. Минор держится только на решении человека; если он его
  не примет — либо 2.0.0, либо эта альтернатива.

## 2026-10-17 · второй раунд ревью

### (A) `--prune` против чужой спецификации — сверх реализованного

Сделано: отказ, если ни один уже сгенерированный тег не остался в спецификации. Не сделано:
запрос подтверждения, когда выбывает заметная доля тегов или файлов (одна-две операции из
сотни — частично неверная спецификация удалит остальное).

- **За:** самый дорогой отказ `--prune` — именно такой; порог дёшев.
- **Против:** любой порог произволен, а `--prune` и так opt-in после списка. Интерактивного
  подтверждения в CLI нет нигде — понадобится `--yes` для CI.
- **С-1 (раунд 3):** сама защита обходится путём из двух шагов — sync без `--prune`, затем с
  ним, — и CLI этот путь советует (честное переименование тегов иначе не пройти). Защита
  ловит ошибку в один шаг, а не намерение. Сильнее — только подтверждение по доле выбывших
  тегов, см. выше.

### (B) `_is_link` считает ссылкой любую reparse point

Сейчас любая точка повторной обработки Windows — не только junction и symlink, но и
заглушки OneDrive Files On-Demand, дедупликация — для генератора «ссылка»: не обходится,
не пишется, не удаляется. Альтернатива — проверять бит name-surrogate тега.

- **За узкую проверку:** проект в каталоге OneDrive сейчас целиком «за ссылкой» — генератор
  ничего туда не пишет (это видно по выводу «Not written — a link»).
- **За текущую:** ложный отказ безопасен и виден; ложный проход через ссылку — запись или
  удаление вне проекта.
- **С-2 (раунд 3), решать вместе с B:** отказ записать через ссылку сейчас даёт код 0 (печатается
  «Not written — a link»), а неудачное удаление при `--prune` — код 1. За единый ненулевой
  код: CI заметит, что дерево не обновилось. Против: если правильна широкая трактовка B,
  проект в OneDrive будет падать с ненулевым кодом на каждом прогоне.

### (C) Старый чек-лист в каталоге исчезнувшего тега

После `--prune` старый `P1_CHECKLIST.md` (пользовательский по правилу B) остаётся, а с ним и
`__init__.py` пакета. Предложение — печатать «оставлено (ваше): …» для таких файлов.

- **За:** иначе остаток каталога выглядит недоработкой генератора.
- **Против:** ещё один список в выводе; файл и так назван подсказкой про старый чек-лист при
  обычном прогоне по живому тегу.

### (D) BOM в нетронутой заготовке — сделано

Заготовка с UTF-8 BOM в начале признаётся заготовкой: BOM не пользовательский текст. Не
спорно по ADR — множество перезаписываемого не расширяется сверх «нетронутой заготовки».

### (E) Подсказка про старый чек-лист — только при `--depth p1`

Чек-листы пишутся только на глубине p1, поэтому и подсказка появляется только там. При
`--depth default` старый чек-лист молча остаётся.

- **За подсказку на любой глубине:** пользователь, перешедший на `default`, не узнает, что
  его чек-лист больше не генераторский.
- **Против:** на `default` генератор чек-листы вообще не ведёт — подсказка была бы о файле,
  который он и так не трогает.
