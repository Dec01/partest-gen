# Предложения

Спорное, что всплыло при работе и **не реализовано**: здесь аргументы обеих сторон, решение
за человеком. Принятое уходит в код и в [[status]], отклонённое — вычёркивается с причиной.

## 2026-10-16 · ревью исправлений 1.2.0

### (a) Смена `--depth` молча оставляет глубокие файлы без обновления

Сейчас `sync-openapi --depth resources` по дереву, сгенерированному с `--depth p1`, не трогает
P1-заглушки и не называет их брошенными — это записано в [[howto/resync]].

- **За строку в выводе:** пользователь, однажды запустивший sync с меньшей глубиной, не
  узнает, что часть сгенерированных файлов больше не обновляется; заглушки разойдутся со
  спецификацией тихо.
- **Против:** меньшая глубина — законный способ обновить только ресурсы; лишний шум в
  выводе каждого такого прогона. Если делать — одной строкой со счётчиком, без списка.

### (b) `pythonpath = .` лечит симптом

Пустой отчёт покрытия при консольном `pytest` закрыт строкой в генерируемом `pytest.ini`.
Настоящая гарантия — в `partest`: сигнал (предупреждение или ошибка), когда `confpartest`
не найден при загрузке плагина, а отчёт пуст.

- **За перенос в `partest`:** проекты, написанные руками или старыми генераторами, остаются
  без защиты; молча пустой отчёт — худший режим отказа.
- **Против того, чтобы убрать строку здесь:** она полезна и после правки в `partest` —
  набор работает одинаково под `pytest` и `python -m pytest`. Предложение — дополнить, не
  заменить. Это задача для `partest`, не для этого репозитория.

### (c) Новая публичная поверхность

По итогам ревью (2026-10-17) публичными оставлены только `find_orphans` и
`remove_orphans` (`partest_gen.emitters.__all__`, сигнатуры — [[components/generator]]);
план генерации и правила владения — приватные (`_plan_resources`, `_is_generated`, …).

- **За публичный план:** он нужен для `--dry-run` (GEN-DIFF в [[status]]) и для обвязок поверх
  генератора.
- **Против сейчас:** потребителя нет; открыть имя потом — минор, закрыть — мажор.

### (d) Честный мажор вместо отдельного признака чек-листа

**Решено 2026-10-18:** поправки ADR banner-overwrite приняты, выпуск 1.2.0; вариант не выбран.

Принятое решение (поправки в [[decisions/banner-overwrite]]) держит минор: чек-лист старого
образца остаётся пользовательским, обновляется только новый образец.

- **За 2.0.0:** один признак баннера для всех файлов, чек-листы во всех проектах сразу
  становятся актуальными; сложность «старый/новый образец» исчезает.
- **Против:** по ADR перезапись по умолчанию там, где её не было, — мажор; ради одного
  справочного файла это дорого, а отметки, сделанные по совету старого текста, были бы
  потеряны молча.

### (e) Минор без правила заготовок

**Решено 2026-10-18:** поправки ADR banner-overwrite приняты, выпуск 1.2.0; вариант не выбран.

Принятое правило (поправки в [[decisions/banner-overwrite]]) перезаписывает файл, побайтно
равный заготовке скелета.

- **Альтернатива:** скелет не пишет заготовки на пути эмиттеров, когда следом идёт
  спецификация (`from-openapi`, `init --openapi`), а при голом `init` пишет их уже с баннером.
  Новые деревья тогда целы без особого признака; старые деревья 1.1.0 чинятся `--force`
  или удалением заготовок руками.
- **За альтернативу:** признак владения остаётся один — баннер; нет списка «известных
  текстов», который надо пополнять при каждой правке скелета.
- **Риск принятого правила:** заготовка `"""Package."""` у `collections/__init__.py`,
  `endpoints/__init__.py`, `validations/__init__.py` неотличима от такого же файла,
  оставленного пользователем нарочно. Если коллекции написаны руками, а `__init__` не тронут,
  sync заменит его сгенерированным с импортами — поведение импорта пакета изменится.
- **Против альтернативы:** заготовки с баннером при голом `init` — это новый «свой» файл там,
  где его не было; старые деревья требуют ручного шага, который правило заготовок снимает.
- **Версия:** по букве «Что было бы мажорной версией» в ADR правило заготовок само — новый
  признак своего файла, то есть мажор. Минор держится только на решении человека; если он его
  не примет — либо 2.0.0, либо эта альтернатива.

## 2026-10-17 · второй раунд ревью

### (A) `--prune` против чужой спецификации — сверх реализованного

Сделано: отказ, если ни один уже сгенерированный тег не остался в спецификации. Не сделано:
запрос подтверждения, когда выбывает заметная доля тегов или файлов (одна-две операции из
сотни — частично неверная спецификация удалит остальное).

- **За:** самый дорогой отказ `--prune` — именно такой; порог дёшев.
- **Против:** любой порог произволен, а `--prune` и так opt-in после списка. Интерактивного
  подтверждения в CLI нет нигде — понадобится `--yes` для CI.
- **С-1 (раунд 3):** сама защита обходится путём из двух шагов — sync без `--prune`, затем с
  ним, — и CLI этот путь советует (честное переименование тегов иначе не пройти). Защита
  ловит ошибку в один шаг, а не намерение. Сильнее — только подтверждение по доле выбывших
  тегов, см. выше.

### (B) `_is_link` считает ссылкой любую reparse point

Сейчас любая точка повторной обработки Windows — не только junction и symlink, но и
заглушки OneDrive Files On-Demand, дедупликация — для генератора «ссылка»: не обходится,
не пишется, не удаляется. Альтернатива — проверять бит name-surrogate тега.

- **За узкую проверку:** проект в каталоге OneDrive сейчас целиком «за ссылкой» — генератор
  ничего туда не пишет (это видно по выводу «Not written — a link»).
- **За текущую:** ложный отказ безопасен и виден; ложный проход через ссылку — запись или
  удаление вне проекта.
- **С-2 (раунд 3), решать вместе с B:** отказ записать через ссылку сейчас даёт код 0 (печатается
  «Not written — a link»), а неудачное удаление при `--prune` — код 1. За единый ненулевой
  код: CI заметит, что дерево не обновилось. Против: если правильна широкая трактовка B,
  проект в OneDrive будет падать с ненулевым кодом на каждом прогоне.

### (C) Старый чек-лист в каталоге исчезнувшего тега

После `--prune` старый `P1_CHECKLIST.md` (пользовательский по правилу B) остаётся, а с ним и
`__init__.py` пакета. Предложение — печатать «оставлено (ваше): …» для таких файлов.

- **За:** иначе остаток каталога выглядит недоработкой генератора.
- **Против:** ещё один список в выводе; файл и так назван подсказкой про старый чек-лист при
  обычном прогоне по живому тегу.

### (D) BOM в нетронутой заготовке — сделано

Заготовка с UTF-8 BOM в начале признаётся заготовкой: BOM не пользовательский текст. Не
спорно по ADR — множество перезаписываемого не расширяется сверх «нетронутой заготовки».

### (E) Подсказка про старый чек-лист — только при `--depth p1`

Чек-листы пишутся только на глубине p1, поэтому и подсказка появляется только там. При
`--depth default` старый чек-лист молча остаётся.

- **За подсказку на любой глубине:** пользователь, перешедший на `default`, не узнает, что
  его чек-лист больше не генераторский.
- **Против:** на `default` генератор чек-листы вообще не ведёт — подсказка была бы о файле,
  который он и так не трогает.

## 2026-10-18 · ревью 1.2.1

### (1) Браузер падает на сертификате голым `net::ERR_CERT_*`

Генерируемый conftest включил проверку сертификатов в браузере. Первый UI-прогон против
стенда с самоподписанным сертификатом падает внутри Playwright: `page.goto` выдаёт
`net::ERR_CERT_AUTHORITY_INVALID`, и переключатель в этой ошибке не назван. У HTTP-клиентов
для этого есть `partest.tls.certificate_error`.

- **За хук в `partest.ui.pytest_plugin`:** ошибка `net::ERR_CERT_*` в упавшем UI-тесте
  дополняется строкой про `PARTEST_TLS_VERIFY` и хранилище браузера — так же, как
  `ApiClient` объясняет свой `ConnectError`. Это работает во всех проектах, а не только в
  сгенерированных, и не требует от генератора своего кода в conftest.
- **Против:** в другом репозитории (`partest`). Ошибки Playwright — это строки, а не типы:
  распознавание по тексту хрупкое при смене версии браузера. Через `pytest_runtest_makereport`
  легко задеть отчёт о совсем другом падении.
- Здесь не делается: это задача для `partest`.

### (2) Нет переключателя TLS только для UI

`PARTEST_TLS_VERIFY=0` выключает проверку сразу и у API-клиентов, и в браузере. Частый
случай — фронтенд на самоподписанном сертификате при API с нормальным — так не выразить.
Отдельный переключатель для одного браузера мог бы опираться на
`--ignore-certificate-errors-spki-list` у Chromium, то есть доверять одному ключу, а не всему
подряд.

- **За:** доверие по SPKI уже, чем «принимать любой сертификат», и не трогает API-клиентов.
- **Против:** только Chromium (у Firefox и WebKit аналога через аргументы запуска нет), это
  аргумент запуска браузера, а не context args, — фикстура `browser_type_launch_args`,
  которую проект может переопределять сам. Новый переключатель — публичная поверхность
  `partest`, а не генератора. Хранилище браузера (ОС, `~/.pki/nssdb` для Chromium на Linux)
  уже решает задачу без кода. Firefox и WebKit `~/.pki/nssdb` не читают — это сказано в
  комментарии генерируемого conftest.

### (3) Код 2 и для неверного ввода, и для сетевого сбоя `--url`

Сейчас `dump-ir`/`sync-openapi`/… выходят с кодом 2 и когда файл битый, и когда URL не
ответил. CI с повторными попытками не отличит «повторить бессмысленно» от «повторить
стоит».

- **За отдельный код (например, 3) для сетевых сбоев:** повтор уместен только там, где он
  может помочь.
- **Против:** код 2 у этих команд уже означает «отказ до записи, причина — во вводе или в
  окружении» (`--entities`, `--prune`, непригодная для записи спецификация). Новый код —
  контракт CLI, который придётся держать. Повтор скачивания проще сделать снаружи: скачать
  файл и подать его через `--file`.

### (4) `--url` генератора мог бы читать `PARTEST_TLS_VERIFY`

Генератор скачивает спецификацию через `requests` с проверкой по умолчанию:
`REQUESTS_CA_BUNDLE` действует, `PARTEST_TLS_VERIFY` нет. Сообщение об ошибке теперь говорит
это прямо.

- **За:** один переключатель на весь проект, как у HTTP-клиентов `partest` и у его
  собственной загрузки спецификации для покрытия.
- **Против:** генератор — инструмент разработчика, а не прогон набора; выключение проверки
  через `PARTEST_TLS_VERIFY=0` в CI заодно молча выключило бы её и при генерации. Если
  делать — только путь к CA-бандлу, без `0`, и через публичный `partest.tls.resolve_verify`
  с его предупреждением.

### (5) `init-package-exports` отказывается работать внутри дерева генератора

Сейчас только справка и документация предупреждают, что запуск на `src/api/resources` отнимает
у генератора его `__init__.py`.

- **За отказ (код 2):** если в каталоге или под ним есть файл с баннером
  `AUTO-GENERATED by partest-gen`, это почти наверняка ошибка; предупреждение в справке
  читают после, а не до. Восстановление — три шага, описанные на странице генератора.
- **Против:** это изменение поведения команды, а сама команда — тонкая обёртка над
  `partest.tools.generate_init`, у которой есть свой вход и которая про баннер ничего не знает.
  Отказ по наличию баннера нужен с флагом-обходом (`--force`), то есть ещё одна поверхность.
  Решение — после выпуска 1.2.1, отдельным минором.

### (6) 2026-10-19 · BOM важнее объявленного charset

Сейчас объявленный в `Content-Type` `charset=` побеждает. UTF-16 с BOM под `charset=utf-8`
даёт ошибку «does not say so», под `charset=latin-1` — кракозябры и ошибку разбора YAML.

- **За BOM первым (как в WHATWG Encoding):** BOM почти не встречается случайно. Ветка «UTF-16
  без charset» исчезла бы, а неверный charset сервера перестал бы ломать спецификацию.
- **Против:** это расходится с правилом «declared charset wins», которое описано в CHANGELOG
  1.2.1 и на странице генератора, а второй порядок пришлось бы объяснять. Ответы с BOM и с
  неверным charset редки, и сообщение уже говорит, что делать: скачать файл.

### (7) 2026-10-19 · библиотечный `load_openapi(url)` отдаёт сырые исключения сети

CLI выводит только имена классов, но `load_openapi()` пропускает исключения requests и urllib3
как есть. В их тексте URL с userinfo и query, и скрипт, который их логирует, это утечка.

- **За обёртку в `SpecReadError` (`stage="fetch"`, исходное исключение без `__cause__`):**
  очищенный текст у всех вызывающих, а не только у CLI.
- **Против:** меняются типы исключений публичной функции. Кто ловил `requests.ConnectionError`,
  перестанет его ловить. Если просто заменить тип, без переходного периода, это мажор. В миноре
  можно только с наследованием от обоих классов: обёртка — подкласс и `SpecReadError`, и
  исходного класса requests или urllib3, так что старые `except` продолжают её ловить.

### (8) 2026-10-19 · единая публичная очистка URL в partest

В `partest` есть свой модуль очистки, `partest.redact` (`redact_text` и другие), и по его
CHANGELOG 2.6.0 сообщения о спецификации теряют учётные данные и query URL. У генератора
своя очистка, `partest_gen._text.redact_source`. Правила
уже разошлись: здесь неоднозначные случаи скрываются целиком.

- **За `partest.redact.redact_url` как одно публичное правило:** одна реализация и один набор
  тестов на утечки. Генератор переходит на неё и поднимает пол `partest`.
- **Против:** это работа в другом репозитории и подъём пола (минор у генератора). Правило «в
  неоднозначных случаях скрывать» для отчёта о покрытии может оказаться слишком строгим:
  там адрес нужен для диагностики.

## 2026-10-25 · ревью кандидата 1.2.2

### (9) Сохранять скачанную спецификацию в `docs/openapi.yaml` — в 1.3.0

Сейчас `--url` ничего не сохраняет: `docs/openapi.yaml` остаётся заглушкой `/health`, и по ней
считают и отчёт о покрытии, и `sync-openapi` без источника. В 1.2.2 сделано только
предупреждение (`Not saved: …`) и строки в документации.

- **За:** ловушка исчезает целиком, без ручного шага. Записывать при тех же условиях, что и
  при `--file`: `init`/`from-openapi` — если файла нет, он меньше 500 байт или передан
  `--force`; `sync-openapi` — если содержимое другое. Тело в JSON сохранять через
  `yaml.safe_dump`, чтобы файл оставался YAML под тем же именем, а в `confpartest.py`
  по-прежнему был `"local"` — без адреса и без учётных данных в коммите.
- **Против:** это новое поведение записи, которое затрагивает чужие репозитории: `sync-openapi
  --url` начнёт переписывать файл, который раньше не трогал. Поэтому минор, а не патч.
  `safe_dump` теряет комментарии и порядок ключей YAML-источника. Для YAML-тела лучше
  сохранять текст как есть, а это два пути записи вместо одного.

### (10) Защита `sync-openapi` от «другого API» без `--prune`

Голый `sync-openapi` против заглушки (или против спецификации чужого сервиса) переписывает
`paths.py` и фасады без путей настоящей спецификации, и уже написанные тесты ломаются ещё до
удаления чего-либо. Защита из (A) срабатывает только с `--prune`.

- **За:** отказ, если ни один из уже сгенерированных тегов не остался в спецификации, или
  предупреждение по доле выбывших тегов. Проверка та же, что у `--prune`, и стоит дёшево.
- **Против:** честное переименование всех тегов — законный случай, и для него понадобится
  `--force` или новый флаг. Переписываются только файлы с баннером, их история есть в git.
  Это не потеря данных, а поломка, которую видно на первом прогоне.

### (11) `assert report.average_pct >= 0` в `test_zorro.py` — тавтология

Заглушка проверяет то, что верно всегда: процент не бывает отрицательным. Тест зелёный и при
пустом отчёте.

- **За настоящую проверку** (например, `report.average_pct > 0` или «хоть один вызов учтён»):
  отчёт без единого учтённого вызова (плагин не загрузился, `confpartest` не найден)
  сейчас проходит зелёным. Отчёт в конце сессии, который обнулял conftest до 1.2.2, этим
  ассертом всё равно не ловится: внутри сессии счётчики ещё целы.
- **Против:** в свежем проекте все заглушки пропущены, и строгий ассерт сделает первый прогон
  красным. Это противоречит «collect-only — приёмка генерации». Отчёт, который пишется в
  конце сессии, всё равно не проверяется тестом внутри сессии. Порог покрытия — решение
  набора, а не генератора.

### (12) Подсказка в `sync-openapi` о `reset_storage()` после `yield`

Деревья до исправления 1.2.2 остаются с обнулением в teardown: `conftest.py` без баннера, sync
его не трогает, и отчёт из нулей молча продолжается.

- **За:** sync и так читает проект. Найти в `src/api/tests/conftest.py` строку
  `reset_storage()` после `yield` и вывести одну строку с советом стоит дёшево; так это
  исправление дойдёт до тех, кто CHANGELOG не читает.
- **Против:** это разбор чужого файла по тексту, и он ошибается на любом переписанном
  conftest. Первый шаг к «линтеру проекта», которого у генератора нет.

### (13) Дописывать `coverage.json` в существующий `.gitignore` при sync

- **За:** в отчёте есть имена хостов стенда (при выключенном TLS) и список эндпоинтов, а
  `init-ui` уже дописывает строки в `.gitignore`. Прецедент есть.
- **Против:** sync начнёт менять файл без баннера. Это новое поведение записи, значит минор,
  и `.gitignore` добавится к контракту баннера как исключение.

### (14) `test_zorro.py` пропускается при `PARTEST_COVERAGE_JSON`

- **За:** с переменной полный отчёт пишется в конце сессии. `test_zorro.py` до этого пишет в
  тот же `coverage_report.html` неполный отчёт, который потом перезаписывается, и добавляет
  в прогон тест, который ничего не проверяет.
- **Против:** заглушка без баннера — существующим проектам не дойдёт. Allure-вложения
  отчёта появляются только из `test_zorro.py`, и кто их смотрит, их потеряет.

### (15) `pytest-xdist` в экстре `dev`

Случай `-n 2` теста `test_the_report_written_at_session_end_counts_the_calls` без xdist
пропускается — в CI так всегда.

- **За:** параллельный прогон — тот случай, ради которого нужен отчёт в конце сессии. Без
  xdist эту ветку не проверяет никто.
- **Против:** ещё одна зависимость разработки со своими уязвимостями и полом. Последовательный
  случай ловит ту же ошибку conftest.

### (16) Два списка заглушек: `_is_placeholder_openapi` и `_RELEASED_PLACEHOLDERS`

`docs/openapi.yaml` сравнивается с текущим текстом скелета, а модули ресурсов — со списком
текстов всех выпущенных скелетов. Если поменять текст заглушки спецификации, деревья со
старой заглушкой перестанут распознаваться, и подсказка `Not saved:` замолчит.

- **За:** перенести заглушку спецификации в `_RELEASED_PLACEHOLDERS` — одно правило
  распознавания, и тексты прошлых выпусков сохраняются.
- **Против:** заглушка спецификации не менялась ни в одном выпуске, а список заморожен
  намеренно — на него опирается перезапись (контракт баннера). Добавлять туда файл, который
  ничто не перезаписывает, — значит смешать назначения.
