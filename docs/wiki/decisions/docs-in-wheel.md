# ADR: документация внутри колеса, `partest_gen/docs` генерируется

**Дата:** 2026-09-06 · **Статус:** принято, схема перенесена из `partest` без изменений

## Контекст

Схема доказала себя в соседнем репозитории: ручное копирование `docs/` → `docs в пакете`
однажды уже увезло в публичный пакет внутренние страницы со статусами и чужими именами.
Там это заменили генерацией по полю `ships_in_wheel`.

Для генератора аргумент даже сильнее. Его запускают из терминала в проекте, где установлен
пакет и нет этого репозитория; вопрос «что делает `--depth p1`» возникает ровно в этот
момент. Отсылать за ответом в браузер — значит не ответить.

## Решение

1. `partest_gen/docs/` **генерируется** из `docs/wiki/` скриптом `tools/docs_build_wheel.py`.
   Руками не редактируется; в шапке каждого сгенерированного файла стоит предупреждение.
2. Что уезжает, решает `ships_in_wheel: true` во frontmatter. По умолчанию — `false`.
3. Внутренние ссылки при генерации разворачиваются в плоские имена файлов, frontmatter
   срезается. Страница, уезжающая в колесо, может ссылаться только на такие же — иначе в
   колесе останется висящий заголовок внутреннего документа.
4. `long_description` — отдельный самодостаточный `docs/PYPI.md`, а не README репозитория.
5. Доступ после установки: `python -m partest_gen.docs list | show <page> | path`.
6. Расхождение `docs/wiki` ↔ `partest_gen/docs` — ошибка линтера и падение
   `tests/test_docs.py`.

## Следствия

- Перед релизом обязателен `python tools/docs_build_wheel.py`; проверка — `--check` в CI.
- Внутренние страницы (статус, журнал, ADR, contribute, release) в колесо не попадают.
- Пользователь получает согласованный набор: как сгенерировать, что с этим делать дальше,
  как пересинхронизировать, что означает баннер, из чего состоит генератор.

## Отклонённые альтернативы

- **Ссылка на документацию соседнего пакета.** Разные пакеты, разные версии; читатель
  получил бы описание команд, которых в его установке может не быть.
- **Внешний сайт документации.** Нет хостинга и нет желания его вести.
- **Пакетировать всю `docs/wiki`.** Тогда посторонние читают внутренний бэклог и статусы.
- **Не возить доки вовсе, отправляя на GitHub.** Ровно тот случай, когда ответ нужен в
  терминале и без сети.
