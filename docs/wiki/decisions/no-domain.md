# ADR: генератор пишет структуру, домен остаётся у проекта

**Дата:** действует с G1, зафиксировано при выделении пакета 2026-09-06

## Решение

Генератор эмитирует форму, а не содержание. Граница проходит так:

| Эмитируется | Всегда остаётся проекту |
|---|---|
| константы путей из спеки | бизнес-значения в теле запроса |
| payload-классы по схеме (форма верная, значения пустые) | обязательные значения предметной области |
| validation-модели по схеме ответа | проверки конкретных полей на смысл |
| фасады коллекций и их фабрика | что положить в коллекцию |
| пустой `roles.py` с чтением из окружения | имена ролей, учётки, RBAC-матрица |
| каркас `security` и `RiskProfile`-обвязка | реестр профилей |
| заглушки P1 с правильным `type=` | сами утверждения |
| `src/ui`: BasePage-наследник, каркас фикстур | селекторы экранов, сцены, PNG-эталоны |
| `.env.example` с именами переменных | значения: URL стендов, пароли, токены |

Ни одна строка эмитируемого кода не должна содержать SQL, удаляющий данные. Очистка идёт
через реестр созданных ресурсов и маркер тестовых данных — то есть удаляется только то, что
прогон сам и создал.

## Почему

Генератор запускают на чужой спеке в чужом репозитории. Любое зашитое доменное допущение —
имя роли, поле, которое «всегда есть», статус, который «всегда 200» — либо неверно, либо
верно случайно. И в отличие от библиотеки, где такое допущение можно переопределить в
рантайме, здесь оно **записывается на диск** и остаётся там навсегда.

Второе: сгенерированное дерево часто коммитят целиком, не читая. Секрет, попавший в шаблон,
попадёт в чужой git-репозиторий, и об этом никто не узнает.

## Заглушка честнее правдоподобного кода

Соблазн — сгенерировать «почти рабочий» тест, догадавшись о значениях по именам полей.
Отклонено: правдоподобная догадка, которая проходит на любом ответе, поднимает цифру
покрытия, ничего не проверяя. Скипнутая заглушка с `TODO` неудобна и честна, и это лучший
из двух возможных обменов. Подробнее — [[concepts/generated-contract]].

## Маркер тестовых данных — не домен

`TEST_MARKER` по умолчанию равен `AQA`: общепринятое сокращение для автоматизации
тестирования, не имя проекта. Он нужен, чтобы очистка находила строки, созданные прогоном, и
не трогала остальное, поэтому пустым не бывает. Проект переопределяет его через
`TEST_DATA_MARKER`. Сам SQL удаления не эмитируется — схема у каждого своя.

## Как проверять

- `tools/docs_lint.py` — приватные пути и имена в страницах, уезжающих в колесо.
- `tests/test_docs.py` — то же самое по исходникам пакета, включая текст шаблонов.
- Ревью: любое имя сущности продукта в `partest_gen/**` — баг, даже в примере в docstring.
