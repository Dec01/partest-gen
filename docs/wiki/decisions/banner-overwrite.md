# ADR: политика перезаписи — по баннеру, а не по имени и не по времени

**Дата:** 2026-09-06 (решение принято раньше, зафиксировано здесь) · **Статус:** принято

## Контекст

`sync-openapi` перезаписывает сгенерированное. Вопрос — как отличить «сгенерированное» от
«написанного руками», когда лежат они в одном дереве и часто в одном каталоге.

Рассмотренные варианты:

1. **По списку имён.** Генератор знает, какие файлы он пишет, и перезаписывает их.
2. **По времени изменения.** Файл новее последнего прогона — значит его правили.
3. **По баннеру в файле.** Перезаписывается то, что помечено как сгенерированное.
4. **По отдельному манифесту** (`.partest/generated.json`).

## Решение

Вариант 3. Файл перезаписывается тогда и только тогда, когда содержит строку
`AUTO-GENERATED by partest-gen`. Флаг `--force` снимает проверку целиком.

## Почему не остальные

**Список имён** ломается ровно в том случае, ради которого всё делается: пользователь
дописал свой тест в сгенерированный файл. Имя совпало — работа потеряна, и узнает он об этом
после `git diff`, если посмотрит.

**Время изменения** не переживает `git clone`, `git checkout` и любой CI. После свежего
клона все файлы новее прогона, значит либо не перезаписываем ничего, либо всё.

**Манифест** — это состояние рядом с файлами, которое обязано с ними совпадать. Он
рассинхронизируется при слиянии веток, при переносе каталога, при откате коммита. И
восстанавливать его придётся по тем же признакам, что и всё остальное.

Баннер живёт внутри файла, поэтому переживает всё, что переживает файл: копирование,
слияние, откат, перенос между репозиториями. И он **виден человеку**: открыв файл, сразу
понятно, будет ли он перезаписан. Ни один из остальных вариантов этого свойства не даёт.

## Последствия

- Удалить баннер — легальный способ забрать файл себе. Это документировано как приём.
- Скопировать сгенерированный файл вместе с баннером — способ потерять копию. Тоже
  документировано; в `howto/resync` это названо явно.
- `--force` остаётся тупым инструментом и должен таким остаться: любая попытка сделать его
  «умнее» возвращает нас к вариантам 1, 2 или 4.
- Проверка перед релизом — найти файлы **без** баннера в сгенерированном дереве. Пропавший
  баннер тихо выводит файл из-под обновлений во всех проектах сразу.

## Поправки — приняты 2026-10-18

Задача: починить первый `from-openapi` без `--force` и обновление чек-листа, оставаясь в миноре по
разделу ниже. По букве раздела «Что было бы мажорной версией» правило заготовок — новый признак своего
файла; минор принят сознательно, потому что совпадение побайтное и пользовательских данных в таком файле нет.

- **Python-файлы — как было.** Признак — полная строка
  `# AUTO-GENERATED by partest-gen — do not edit by hand.` в любом месте файла, как во всех выпусках до сих пор.
  Никакой более широкой формы не принимается.
- **`P1_CHECKLIST.md` — отдельный признак.** Баннер в Markdown — та же строка без `# `
  (иначе заголовок), и файл генератора, только если он **первая** строка и в файле есть
  строка ровно `Rewritten on every sync.` — отдельным абзацем, чтобы форматтер Markdown её не
  переносил. Чек-лист старого образца (`Mark when implemented for real.`,
  все выпуски до этого изменения) звал отмечать руками — он пользовательский: sync его не трогает и печатает
  подсказку «удалите файл, чтобы получить обновляемый».
- **Заготовки скелета.** Файл, побайтно равный тексту заготовки скелета (любого выпуска по
  git-истории, LF или CRLF, с BOM или без) на пути, который пишут эмиттеры ресурсов, перезаписывается без
  баннера: в нём нет ничего пользовательского. Хоть строка правки — файл пользователя.
  Риск, который правило принимает: заготовка из одной строки `"""Package."""` у `collections/__init__.py`,
  `endpoints/__init__.py`, `validations/__init__.py` ничем не отличима от такого же файла,
  оставленного пользователем нарочно. Проект, где коллекции написаны руками рядом с
  нетронутым `__init__`, после sync получит сгенерированный `__init__` с импортами — поведение
  импорта пакета изменится. Минорная альтернатива без этого риска — в [[proposals]], пункт (e).
- **Ссылки.** Генератор не пишет и не удаляет по пути, на котором есть symlink или junction,
  и ничего, что разрешается вне проекта; такие пути он перечисляет.
- **Версия.** По букве раздела ниже правило заготовок — новый признак «своего» файла, то есть
  мажорная версия. Минорный номер держится только на решении человека принять эти поправки;
  без него честный номер — следующий мажорный, либо альтернатива (e) из [[proposals]].
- **Брошенные файлы.** Файлы генератора (Python — баннер первой строкой; чек-лист — новый
  образец), которых ни одна операция спецификации больше не порождает, `sync-openapi`
  перечисляет; удаляет только `--prune`. Удаление по умолчанию было бы «перезаписью по
  умолчанию там, где её не было».

## Что было бы мажорной версией

Любое расширение множества перезаписываемых файлов: новый признак «своего» файла, баннер в
другом формате, перезапись по умолчанию там, где её не было. С точки зрения пользователя это
неотличимо от потери данных, и предупреждать об этом надо номером версии.
